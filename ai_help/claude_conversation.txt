Wrote and presented a plan (approved by the user) covering:

1. Environment: `git clone` the jito-dev/jito-intern-test-task template (branch
   develop) into the working directory.

2. Parser architecture - two layers, mirroring htmlparser2:
   - Tokenizer: a character-index scanner (indexOf/manual checks, not heavy
     backtracking regex) recognizing: <!DOCTYPE ...>, <!-- comments --> (including
     unterminated ones), <![CDATA[ ]]>, start tags with attributes (quoted/
     unquoted/boolean, self-closing "/>"), end tags, text with entity decoding,
     and two special categories:
       * "raw text" elements (script, style) - content taken literally up to the
         matching end tag, so "<", ">", quotes inside JS/CSS don't get parsed as
         markup;
       * "escapable raw text" elements (textarea, title) - not parsed as markup,
         but entities inside are still decoded (relevant because index.html's
         "Input Example 2" uses a <textarea> with a long string).
   - Tree builder: a stack of currently-open elements.
     * void elements (area, base, br, col, embed, hr, img, input, link, meta,
       param, source, track, wbr) never expect a closing tag;
     * a closing tag with no matching opener on the stack is ignored (stray tag);
     * a closing tag matching an ancestor implicitly closes everything opened
       after that ancestor too;
     * anything left open at end-of-input is implicitly closed.

3. Crash-proofing (the task's hard requirement):
   - the whole function wrapped in try/catch, falling back to a safe
     { type: "root", children: [], error: "..." } instead of throwing;
   - guards for non-string/null/undefined input;
   - the tokenizer loop guarantees forward progress every iteration (force-advances
     by one character if nothing matched), so it cannot hang;
   - avoids quadratic string concatenation for large inputs.

4. JSON shape (chosen and justified): a discriminated-union style close to
   htmlparser2/hast conventions -
     root:    { type: "root", children: [...] }
     element: { type: "element", name, attributes, children }
     text:    { type: "text", value }
     comment: { type: "comment", value }
     doctype: { type: "doctype", value }
   Rationale: self-describing, easy to walk/serialize/test, and a "root" wrapper
   naturally supports zero or multiple top-level nodes (as in Example 2's bare
   <div> fragment) without a special case.

5. html_samples/ fixtures to cover: simple nesting, attribute variations, void
   elements, malformed/unclosed/overlapping tags, script/style raw content,
   comments+doctype, textarea+entities (mirrors Example 2), and Unicode/CDATA/
   stray-bracket edge cases.

6. A zero-dependency Node smoke test (test/run-samples.js, using only the
   built-in "assert" module) running html2json over every sample plus a set of
   intentionally adversarial inline inputs (null/undefined/non-string, empty/
   whitespace-only, 2000 levels of nesting, a 500k-character string, unterminated
   tags/comments/attributes, mismatched nesting), asserting it never throws and
   always returns JSON-serializable output.

7. ai_help/: noted that chatgpt_chat.txt as specified assumes ChatGPT, but this
   session uses Claude, so a placeholder/explanation would be needed instead of a
   literal ChatGPT link.

8. README.md: add a "Solution notes" section explaining the JSON shape, the edge
   cases handled, and known limitations, without rewriting the whole document.

IMPLEMENTATION (performed by the assistant):

- Cloned jito-dev/jito-intern-test-task (branch develop) into the working
  directory.
- Rewrote html2json(htmlText) in html2json.js: a tokenizer (tokenize) producing
  startTag/endTag/text/comment/doctype tokens, plus a tree builder (buildTree)
  turning those tokens into the root/element/text/comment/doctype tree described
  above, including:
    * VOID_ELEMENTS / RAW_TEXT_ELEMENTS / ESCAPABLE_RAW_TEXT_ELEMENTS tables,
    * a decodeEntities() helper for named (&amp; etc.) and numeric (&#169;,
      &#x1F600;) character references, leaving unrecognized entities untouched,
    * an attribute parser handling double/single/unquoted/boolean attributes and
      self-closing "/>",
    * stray/mismatched end-tag handling and implied closing of ancestors,
    * a top-level try/catch fallback and non-string input coercion,
    * a forced-progress safety net in the tokenizer loop to prevent infinite
      loops,
    * a `module.exports` guard at the end so the same file works unchanged both
      as a browser <script> global and via `require()` in the Node test script.
- Created html_samples/: simple.html, attributes.html, void-elements.html,
  malformed.html, script-style.html, comments-doctype.html,
  textarea-entities.html, edge-cases.html.
- Created test/run-samples.js: runs html2json over every html_samples/ file plus
  13 inline adversarial cases (null, undefined, number input, empty/whitespace-
  only, a lone "<"/">", 2000 levels of nested <div>, a 500k-character string,
  an unterminated <script>, an unterminated attribute value, a self-closing
  non-void element, mismatched nesting) and asserts none of them throw and all
  produce JSON-serializable output. Result: 22 passed, 0 failed.
- Created ai_help/chatgpt_chat.txt noting that Claude (not ChatGPT) was used,
  with a placeholder for the conversation link.
- Extended README.md with a "Solution notes" section: approach, JSON shape and
  rationale, the specific edge cases handled (void elements; script/style raw
  text; textarea/title escapable raw text; unclosed/stray/ancestor-matching
  closing tags; unterminated comments/CDATA/attributes/tags; quoted/unquoted/
  boolean attributes; named and numeric entity decoding; the try/catch safety
  net and forced-progress guarantee), and known limitations (no SVG/MathML
  foreign-content rules or HTML5 implied-tag rules beyond the generic ancestor-
  match rule; `<div/>`-style self-closing is honored for non-void elements as a
  deliberate, documented deviation from strict HTML5 parsing).
- Verified: `node test/run-samples.js` → 22 passed, 0 failed. Manually inspected
  JSON.stringify output for several representative and edge-case inputs
  (nested elements with attributes/comments, mismatched nesting, self-closing
  non-void elements) to confirm the tree shape was sensible.
